## 〇、先回答一个根本问题

> **我们到底在做什么？**

这个问题必须每隔一段时间重新回答一次。因为做着做着会漂移。

**2026-07-23 的答案:**

我们不是在做工具，不是在做 SaaS，不是在做平台。
我们在做 **Agent 世界的 "你是谁" 层**。

类比：
- TCP/IP 解决了"怎么连"
- DNS 解决了"叫什么"
- **Alpha-ID 解决了"你是谁"**

Agent 越来越多，但没有一个东西让 Agent 认识你。每次用新 AI 工具都像遇到陌生人。Alpha-ID 就是让所有 Agent 都能识别你的那张"数字身份证"——不只是名字，是你的偏好、习惯、历史、能力边界。

**隐含的洞察**: 当 Agent 足够多的时候，"认识你"比"能用你"更有价值。能用你的工具会迭代、会倒闭，但"认识你"的数据是累积的、不可重置的。这就是护城河。

## 三、身份与验证: 你的 DID 就是你的数字分身

> 来源: 7/23 对话新思考 · AID 41/ 目录身份层 · 竞品检索报告身份轨道

### 3.1 核心设计: 身份证 + 人脸 = 唯一 Alpha-ID

**你的直觉是对的**: 必须用具有唯一性的东西（身份证），而不是自生成的密钥对。自生成的密钥对无法证明"你是你"。

```
注册流程:
                                    
  ① 输入姓名 + 身份证号           
         │                        
         ▼                        
  ② 调用支付宝/微信 实名认证 API   
     （二要素验证：姓名+身份证）    
         │                        
         ▼                        
  ③ 人脸活体检测                   
     （支付宝/微信/旷视 Face++）    
         │                        
         ▼                        
  ④ 生成唯一 Alpha-ID 编号         
     格式：AID-{YYYYMMDD}-{序号}   
     例：AID-20260722-00001        
         │                        
         ▼                        
  ⑤ Ed25519 密钥对本地生成         
     私钥永不上传，仅存本地         
```

**为什么这样设计:**
- 身份证 + 人脸 = 保证唯一性（一人一证一号）
- 本地生成密钥 = 保证隐私性（平台不持有私钥）
- 全局递增编号 = 可展示性（"你是第 10001 位用户"有仪式感）

### 3.2 认证 API 选择

| 服务商 | 费用 | 准确率 | 推荐 |
|--------|------|--------|------|
| 支付宝实名认证 | 0.5-1 元/次 | 99.9% | ✅ 最推荐 |
| 微信实名认证 | 0.5-1 元/次 | 99.9% | ✅ 推荐 |
| 旷视 Face++ | 0.3-0.8 元/次 | 99.5% | 🟡 备选 |
| 百度 AI | 0.3-0.5 元/次 | 99.3% | 🟡 备选 |

**推荐**: 支付宝 + 微信双通道, 用户自选。成本约 1 元/注册。

## 四、记忆双链架构: 私链与知链

> 来源: 7/23 对话新思考 · AID 41/ 目录记忆系统 · Kimi 分析 Obsidian 集成

### 4.1 为什么需要两条链

你的直觉是对的: 记忆不能一概而论。有两类记忆:
1. **私链**: 我的对话历史、行为指纹、偏好、生物特征哈希 — 绝不外传
2. **知链**: 我的学习笔记、收藏、Obsidian vault、公开知识 — 部分可共享

如果混在一起:
- 用户担心隐私 → 不愿意上传任何东西 → 记忆系统空转
- 或者全部公开 → 隐私灾难

分开后:
- 用户放心把私链留在本地 — 零信任风险
- 知链可以自由同步、共享、甚至变现

### 4.2 双链架构

```
┌─────────────────────────────────────────────────────────────────┐
│                     Alpha-ID 记忆系统                            │
├──────────────────────────┬──────────────────────────────────────┤
│   私链 (Private Chain)    │   知链 (Knowledge Chain)              │
├──────────────────────────┼──────────────────────────────────────┤
│                          │                                      │
│ • DID 身份数据            │ • 学习笔记/收藏                      │
│ • 对话历史（加密）        │ • 短视频摘要/标签                    │
│ • 行为指纹               │ • 技能学习记录                       │
│ • 偏好/习惯              │ • Obsidian vault 同步                │
│ • 生物特征哈希           │ • 公开知识图谱                       │
│ • 凭证碎片               │ • 内容创作素材                       │
│                          │                                      │
├──────────────────────────┼──────────────────────────────────────┤
│ 存储: 本地加密 SQLite     │ 存储: Obsidian 兼容格式 + 可选云同步  │
│ 访问: 仅本人 + 授权 Agent │ 访问: 本人 + 授权 + 可公开部分       │
│ 格式: 结构化 Profile      │ 格式: Markdown + YAML frontmatter    │
│ 加密: AES-256-GCM         │ 加密: 可选                           │
│                          │                                      │
│ 原则: 数据永远在你手里    │ 原则: 创作即沉淀, 沉淀即价值          │
└──────────────────────────┴──────────────────────────────────────┘
```

### 4.3 Obsidian 集成方案

Obsidian 已经验证了个人知识库的需求。我们不是重新发明, 而是兼容:

```
用户工作流:
                                    
  ① 用户在刷抖音/小红书         
         │                        
         ▼                        
  ② 看到有价值的内容             
     → 一键收藏到 Alpha-ID        
     → AI 自动摘要 + 打标签        
         │                        
         ▼                        
  ③ 知链接收:                   
     — 原文链接 (可回溯)          
     — AI 摘要 (200字内)          
     — 标签 (自动 + 手动)         
     — 分类 (学习/工作/兴趣)      
         │                        
         ▼                        
  ④ 写入 Obsidian vault:        
     — 标准 Markdown              
     — YAML frontmatter 包含元数据

     — 自动打标签 #AI #电商 #出行

         ▼
```

### 4.4 为什么 Obsidian 是正确的选择

1. **用户已有习惯**: 大量知识工作者已在用 Obsidian

4. **本地优先**: 和我们的"数据在你手里"理念一致
5. **可视化**: 知识图谱、关系图, 天然适合展示 Profile 的关联

## 五、Token 经济: 让 Agent 用得放心

> 来源: 7/23 对话新思考 · ECOSYSTEM_ARCHITECTURE 商业版 · 全方位规划书

### 5.1 核心矛盾

**人类浏览 = 免费, Agent 执行 = 付费。**
这就像看短信列表免费, 发短信按条收费。

但如果用户不知道 Agent 在后台花了多少钱, 就会产生恐惧:
> "万一 Agent 一晚上把我的钱烧光了怎么办?"

### 5.2 五层防护设计

```
┌─────────────────────────────────────────────────────────────────┐
│  Layer 1 | 日预算上限                                            │
│  用户设置每日最大消耗（默认 10 元/天）                             │
│  超出后 Agent 进入只读模式, 不执行任何付费操作                     │
├─────────────────────────────────────────────────────────────────┤
│  Layer 2 | 单次调用上限                                          │
│  单次 Agent 调用最多消耗 X tokens（默认 5000）                     │
│  超出需用户手动确认                                              │
├─────────────────────────────────────────────────────────────────┤
│  Layer 3 | 速率限制                                              │
│  每分钟最多 N 次 Agent 调用（默认 10 次/分钟）                     │
│  防止死循环耗尽                                                  │
├─────────────────────────────────────────────────────────────────┤
│  Layer 4 | 睡眠模式                                              │
│  夜间 23:00-08:00 Agent 自动休眠                                 │
│  仅响应紧急任务（用户可自定义）                                   │
├─────────────────────────────────────────────────────────────────┤
│  Layer 5 | 实时余额告警                                          │
│  余额 < 20% → 推送通知                                          │
│  余额 < 5%  → Agent 暂停, 等待充值                               │
│  余额 = 0   → 只读模式, 可浏览不可执行                           │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 额外安全阀

| 机制 | 触发条件 | 动作 |
|------|---------|------|
| 异常熔断 | 1 小时内消耗 > 50% 日预算 | 自动暂停, 需用户解锁 |
| 大额确认 | 单次操作 > 1 元 | 弹窗/推送确认 |
| 新用户保护 | 注册 7 天内 | 日预算上限 5 元 |
| 透明计费 | 每笔消耗 | 实时显示 token 数 + 折算金额 |
| 账单明细 | 每日/每周 | 推送消耗报告 |

### 5.4 支付系统设计

**不用虚拟币, 用法币锚定积分:**

```
┌──────────────────────────────────────────────────────┐
│  用户法币 → 平台积分（1:1 锚定人民币）                  │
│  （支付宝/微信/银行卡入金）                             │
├──────────────────────────────────────────────────────┤
│  平台积分 → Agent 服务消耗（按 token/调用计费）          │
│  （内部结算, 用户无感）                                │
├──────────────────────────────────────────────────────┤
│  平台积分 → 提现回法币（T+1, 手续费 1%）               │
│  （创作者变现通道）                                    │
└──────────────────────────────────────────────────────┘
```

**为什么不用虚拟币:**
- 监管风险: 中国对虚拟货币有严格管控
- 用户认知: 普通用户不理解"代币"
- 合规: 法币通道走支付宝/微信, 天然合规

**积分命名建议**: "星点" (和星链主题呼应) 或直接叫"积分"。

### 5.5 收费模式

| 环节 | 收费 | 理由 |
|------|------|------|
| 注册/登录 | **免费** | 门槛必须为零 |
| 身份验证 | 平台承担 | 获客成本, 约 1 元/人 |
| 人类浏览 | **免费** | 用户无感使用 |
| Agent 执行 | 按 token 计费 | 用多少付多少 |
| 技能交易 | 平台抽 10% | 标准比例 |
| 提现 | 1% 手续费 | 覆盖支付通道成本 |

> **注册绝对不能收费。** 靠生态内的交易抽成和 Agent 服务计费, 不是卖门票。

## 六、平台规则: 当好生态的管家

> 来源: 7/23 对话新思考 · ECOSYSTEM_ARCHITECTURE 安全防护

### 6.1 平台定位

**你不是卖产品的, 你是管生态的。**

类比:
- 苹果 App Store = 管应用生态
- 淘宝 = 管商品生态
- **Alpha-ID = 管 Agent 生态**

你的职责:
1. 让好 Agent 被找到
2. 让坏 Agent 被识别
3. 让交易公平透明
4. 让用户数据安全

### 6.2 核心规则

| 规则 | 内容 | 原因 |
|------|------|------|
| **身份唯一** | 一人一证一 ID, 不可转让, 不可多开 | 防刷分、防机器人 |
| **技能审核** | 上架技能需通过安全扫描 + 人工审核 | 防恶意 Agent |
| **隐私优先** | 用户数据默认本地, 上传需明确授权 | 合规 + 用户信任 |
| **透明计费** | 每笔消耗可追溯, 走哪条路径、为什么收费全部可见 | 建立信任 |
| **争议仲裁** | 技能交易纠纷由平台仲裁, 冻结资金 | 保护双方 |
| **退出机制** | 用户可随时导出全部数据, 注销 ID | 数据主权 |
| **免费优先** | 能走免费路径就免费, 超出后才付费, 用户自愿升级 | 降低门槛、建立信任 |
| **路径透明** | 告知用户"走的是哪条路径、消耗了什么、为什么收费" | 避免"暗箱操作"质疑 |

### 6.3 Agent 信任分级

```
所有 Agent 都可以注册, 但是:

🔒 未验证 — 仅可被用户手动调用, 不可被其他 Agent 调用
🥉 铜牌   — 可被 Agent 调用, 但调用方会看到声誉低
🥈 银牌   — 标准调用, 正常显示
🏆 金牌   — 首页推荐, 优先匹配

等级自动调整, 不人为干预。
```

### 6.4 技能收益分配

```
每笔 $10:
  执行者 $7.5 (75%)  |  创建者 $1.0 (10%)
  平台   $1.0 (10%)  |  生态基金 $0.5 (5%)

技能学习者 (A) 与原创者 (B):
  A 的前 100 次调用向 B 交 5% 学徒费
  100 次后 A 独立
```

### 6.5 技能系统新模型: 从"固定收费"到"路由决策树"

> **来源**: 7/23 深度讨论 — 发现"技能 = 固定 API 端点 → 收费"模型的根本矛盾

**旧模型的问题:**
```
技能 = 一个 API 端点 → 调用 → 固定收费 0.5 元
问题: 用户发现豆包免费就能生成, 凭什么付 0.5?
       平台如果暗地里调豆包, 免费额度谁出?
```

**新模型: 技能 = 路由决策树 + 多路径执行**

```
"我需要产品图片" 的完成路径:

  路径 A: 用户自己有专业图 → 直接用 (免费)
  路径 B: 用户有手机实拍 → AI 增强 (免费池/低成本)
  路径 C: 用户有参考图 → 图生图 (免费池/中成本)
  路径 D: 用户什么都没有 → 文生图 (免费池/高成本)
  路径 E: 用户要摄影棚效果 → 付费 API (最高成本)
```

**技能的配置化定义 (非代码):**

```yaml
# skill: product-image-generator v1.2
name: 产品图生成
description: 根据用户素材生成专业产品图

routing:
  - condition: "user_has_professional_image"
    action: use_directly
    cost: 0

  - condition: "user_has_phone_photo"
    action:
      provider: doubao-image-edit
      prompt_template: "将 {user_image} 处理为白底专业产品图"
      cost: 0  # 免费池
    fallback:
      provider: jimeng-image
      cost: 0.3

  - condition: "user_has_nothing"
    action:
      provider: doubao-text2image
      prompt_template: "专业白底产品摄影, {product_name}, 电商用图"
      cost: 0
    fallback:
      provider: jimeng-text2image
      cost: 0.5

learning:
  # 技能自动学习哪条路径效果最好
  track: [success_rate, user_satisfaction, cost_efficiency]
  auto_promote: true
```

**更新技能 = 改 YAML 配置 = 30 秒搞定, 不是改代码。**

**免费额度解决方案 — 混合模式:**

```
免费层: 平台批量购买豆包/通义/文心配额 (量大从优)
       → 每天前 N 次调用免费
       → 超出后自动切换付费池

付费层: 超出免费配额后
       → 用户选择: 继续付费 or 等明天刷新

技能创建者可选:
  → "自带 API Key": 走自己的配额, 平台不收费
  → "使用平台池": 走平台配额, 平台抽成
```

**收费策略: 免费试用 + 付费升级**

| 层级 | 成本 | 质量 | 策略 |
|------|------|------|------|
| 免费层 | 0 元 | 够用 | 豆包/通义免费池, 建立信任 |
| 基础层 | 0.2-0.5 元 | 更好 | 即梦/文心付费 API |
| 专业层 | 1-5 元 | 专业 | Midjourney/定制服务 |

**关键转变: 从"收费服务"到"免费试用 + 付费升级"。用户先免费用, 觉得值才付钱。**

**技能组合: 平台 = 技能编排器**

```
用户: "帮我上架这个产品"

平台编排:
  ① 产品图生成 → 豆包免费池 → 0 元
  ② 描述撰写 → 豆包免费池 → 0 元
  ③ 关键词优化 → 豆包免费池 → 0 元
  ④ 价格建议 → 本地算法 → 0 元
  ⑤ 一键上架 → 平台服务 → 0 元

汇总: "全部完成! 总费用: 0 元 (免费额度内)"
```

**核心原则总结:**
1. 能免费就免费 (建立信任)
2. 免费不够才付费 (用户自愿)
3. 技能是配置不是代码 (更新简单)
4. 技能可组合 (平台编排)
5. 技能能学习 (自动优化路径)
6. 透明告知用户 (走的是哪条路径, 为什么收费)

> 来源: 7/23 对话 iPhone 壳场景 · ECOSYSTEM_ARCHITECTURE 用户旅程

### 7.1 场景: 用户卖 iPhone 15 防摔壳 (路由决策树版)

```
用户: 我要卖 iPhone 15 防摔壳
  │
  ▼
平台: 请上传产品图片
  │
  ▼
用户: 没有专业图片, 只有手机里一张实拍
  │
  ▼
平台路由决策:
  │
  ├─ 检测到: 用户有手机实拍图
  │
  ├─ 匹配技能: product-image-generator
  │
  ├─ 走路径 B (手机实拍 → AI 增强)
  │   ├── provider: 豆包图生图 (免费池)
  │   ├── 免费池剩余: 998/1000 → 够用
  │   ├── prompt: "将这张手机实拍图处理为白底专业产品图, 保持产品细节"
  │   └── 调用豆包 → 返回结果
  │
  └─ 告知用户: "✅ 已生成! (使用免费额度, 今日剩余 997 次)"
  │
  ▼
用户: 满意 → 上架成功 (总费用: 0 元)
  │
  └── 不满意 → "要不要试试更专业的? (0.5元, 即梦生成)"
                    ├── 好 → 收费 0.5 元, 重新生成
                    └── 不用了 → 结束 (0 元)
```

**这个场景为什么重要:**
- 它验证了平台的路由决策能力 (不是固定收费, 是智能选路径)
- 它展示了"免费试用 + 付费升级"模式 (先免费, 满意才付)
- 它是一个可复用的"加速交付"模板
- 它让卖家从"没图卖不了"变成"有图就能卖"
- 它解决了"豆包免费, 凭什么收我钱"的矛盾

## 十四、宣传与营销

> 来源: ECOSYSTEM_ARCHITECTURE 宣传策划

### 14.1 核心叙事

```
对外一句话 (旧):
  "Ghost 是坐在所有 AI 工具之上的 Ghost Layer。你负责创造能力, 我们负责让你被找到、被验证、被调用。"

对外一句话 (新):
  "你说要卖手机壳, 30 秒完成。图、描述、关键词、上架, 全部自动。"

三层叙事:
  对开发者: "写一个技能, 平台帮你找到需要它的人, 自动编排到流程中"
  对博主:   "你只管创作, 平台自动适配分发到 7 个平台"
  对普通用户: "一句话完成任何事, 平台自动调度最合适的技能"
```

### 14.1.1 为什么改了

"Agent 的淘宝"是**市场模式**——用户自己逛、自己选、自己组合。
新的叙事是**路由模式**——用户说需求, 平台自动编排。

市场模式适合工具丰富的开发者。路由模式适合所有人。
**我们要做的是让"什么都不懂的人"也能用 Agent 完成复杂任务。**

### 14.2 分阶段宣传

```
Phase 1 (Month 1-2): 种子期 — 不宣传, 只找 10 个种子用户

Phase 3 (Month 5-8): 增长期 — 案例营销 + 社区运营
Phase 4 (Month 9-12): 规模化 — 品牌 + 渠道
```

## 十五、我们的护城河到底是什么

> 这是每隔一段时间必须重新回答的问题。

### 版本 1 (2026-07-23)

**短期护城河 (0-6 月): 执行验证 (Trial Call)**
- 每个 Agent 必须通过实际运行测试才能上线
- 这不是"说自己能做什么", 是"跑出来证明"
- 这个机制几乎没有竞品在做

**中期护城河 (6-12 月): 记忆 + 身份的数据飞轮**
- 用户用得越久, Profile 越丰富, 迁移成本越高
- 私链数据不可导出到其他平台 (本地加密)
- 知链知识图谱随时间自然生长

**长期护城河 (12 月+): 协议层**
- AID + A2A 成为开放协议
- 任何人可以构建兼容实现
- 平台是协议的最大运营方, 但不是控制方

### 护城河的本质

> **不是技术, 是信任 + 智能。**
> 
> 当一个 Agent 的声誉分是 87 分、有 12000 次成功调用、被 328 个用户评分 4.6 —— 这个数据是不可伪造的 (PoE 链), 不可迁移的 (平台绑定), 不可刷新的 (时间积累)。
> 
> 当平台能在用户说"我要卖手机壳"时, 自动编排 5 个技能、智能选择免费路径、30 秒完成全流程 —— 这种"智能路由"能力是任何单一技能无法替代的。
> 
> 这就是护城河。

## 十六、今日新思考汇总

> 以下是在 7/23 对话中涌现的、但尚未落入上述章节的新想法。它们可能是下一步的种子。

### 16.1 盘子会不会太大?

**会。** 所以必须分阶段切:
- P0 = 身份 + 私链 + 基础 Profile + Token 防护
- 其他全部延后
- 每完成一个 Phase, 重新评估范围

### 16.2 注册收费合理吗?

**不合理。** 注册必须免费。收入来自:
- Agent 服务计费 (用多少付多少)
- 技能交易抽成 (10%)
- 增值服务 (高级凭证库、数据分析)

### 16.3 身份证验证的成本?

约 1/注册。平台承担, 算获客成本。
- 1000 用户 = 1000 元验证成本
- 如果 10% 付费 = 100 付费用户
- 每用户月消费 10 元 = 1000 元/月收入
- 验证成本 1 个月回本

### 16.4 Agent 调度技能加速交付

这是一个可以标准化的模式:
```
用户有需求 → 平台判断能力缺口 → 调度技能 Agent → 加速交付
```
- iPhone 壳场景 = 产品图生成
- 视频场景 = 封面生成/自动剪辑
- 电商场景 = 产品描述/关键词优化

### 16.5 子项目命名最终建议

推荐星链主题: nebula / pulse / alphaid / core / stage / flow
- 简洁 (2-6 字母)
- 好发音
- 有科技感
- 和星链模型呼应
- 国际化

### 16.6 技能系统: 从固定收费到路由决策树

**这是今天最重要的范式转变。**

旧模型"技能 = API 端点 → 固定收费"有一个根本矛盾: 用户发现豆包免费就能生成图, 凭什么付 0.5?

新模型: 技能 = 路由决策树 + 多路径执行。能免费就免费, 免费不够才付费, 用户自愿升级。

核心洞察: **平台不是卖技能, 是编排技能。** 技能的"智能"不在于代码多复杂, 而在于路由决策树配置得多好。更新技能 = 改 YAML = 30 秒。

详细设计见 §6.5。

### 16.7 平台定位再确认: 智能路由器

之前说"平台 = Agent 的淘宝"。现在更精确: **平台 = 需求的智能路由器**。

用户说"我要卖手机壳", 平台不是把用户扔到一个技能市场让他自己选, 而是:
1. 理解需求 (需要图、需要描述、需要上架)
2. 评估用户有什么 (有实拍图、无描述、无价格)
3. 自动编排技能链 (图生成 → 描述撰写 → 关键词优化 → 上架)
4. 智能选路径 (免费池优先, 超出才付费)
5. 交付结果 (一句话完成)

**从"市场模式"到"路由模式"。这是差异化的核心。**
