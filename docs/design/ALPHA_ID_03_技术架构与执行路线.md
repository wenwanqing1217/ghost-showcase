## 一、四层架构（精简版）

原有的七层架构（DID + Profile + 记忆 + 因果 + 采集 + MCP + A2A）保留为完全体的设计参考。当前实现聚焦为四层：

```
┌─────────────────────────────────────────────────────────┐
│                    Ghost Layer                          │
│                 （后台常驻，用户无感）                    │
└─────────────────────────────────────────────────────────┘
                            │
          ┌─────────────────┼──────────────────┐
          ▼                 ▼                   ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│  身份层           │ │  画像记忆层       │ │  MCP 注入层      │
│  DID + Ed25519   │ │  Profile + 3层记忆 │ │  暴露给所有 AI  │
│  客户端私钥       │ │  + 因果图谱       │ │  工具            │
│  签名验证         │ │  + 采集器         │ │                 │
└──────────────────┘ └──────────────────┘ └──────────────────┘
          │                   │                     │
          └───────────────────┼─────────────────────┘
                              ▼
                    ┌──────────────────┐
                    │  AI 工具生态      │
                    │ ChatGPT / Claude  │
                    │ Cursor / Windsurf │
                    └──────────────────┘
```

## 三、v1.0 实现范围（全能力展示）

### 3.1 什么是"全能力展示"

```
v1.0 不是最小可用版。v1.0 是 "这个项目到底在做什么" 的完整演示版。

它应该让用户在 10 分钟内体验到：
  ✅ 身份存在感：看到自己的 DID 身份
  ✅ 被认识感：看到画像上有自己的风格分析
  ✅ 跨工具感：通过 MCP 注入到 Claude Desktop
  ✅ 互动感：通过 Web 端看到自己的数字胚胎
  ✅ 游戏感：在模拟盘中跟精灵互动
  ✅ 社交感：看到其他用户的化身在星链中

v1.0 不做完美的版本——功能要做到，体验可以粗糙，Bug 可以有。
v2.0 才是打磨和优化。
```

## 四、技术决策记录

| 决策项 | 决定 | 原因 |
|:-------|:-----|:------|
| 结构化数据库 | SQLite（默认） | 本地优先，零配置 |
| 向量数据库 | ChromaDB（嵌入式） | 本地运行，支持语义搜索 |
| DID 实现 | Ed25519 + did:aid: | W3C 标准，轻量 |
| CLI 框架 | typer | 类型安全，自动生成帮助 |
| MCP 实现 | 官方 Python SDK | 与生态兼容 |
| 前端框架 | Three.js（3D）+ 原生 HTML/CSS | 灵活，不需要 React/Vue 的构建工具链 |
| Web 端状态 | IndexedDB | 数据不出本地 |
| 实时同步 | 公共 JSON 轮询（初期） | 零服务器成本 |
| 因果图谱存储 | SQLite 表 | 简单可靠，支持级联 |
| 模拟盘精灵 AI | 有限状态机 + JSON 规则 | 不需要 LLM，轻量，可控 |
