# 模拟盘 · 数字创世纪 完整设计

> 子项目设计文档 | 配合《项目总纲》和《Web端与产品设计》阅读
> 这是 Alpha-ID 的"体验层 + 数据采集器 + 病毒传播器"

---

## 一、定位：这不是游戏

```
  ❌ 不是"附属品"——你完成主项目后有空再做的东西
  ❌ 不是"营销工具"——只为了吸引流量的噱头
  ❌ 不是"教学关卡"——教完用户如何使用就结束的东西
  
  ✅ 它是 Alpha-ID 的"可体验式说明书"
     ——用户不需要读文档，玩 5 分钟就理解"外置大脑"是什么
  
  ✅ 它是 Alpha-ID 的"数据采集场"
     ——用户在游戏中的每一次决策都是训练外置大脑的饲料
  
  ✅ 它是 Alpha-ID 的"病毒传播器"
     ——"你看我的精灵多聪明"比任何技术白皮书都好传播
  
  ✅ 它是 A2A 协议的"最小试验场"
     ——精灵之间的互动就是未来 Agent 社交的预演
```

### 一句话总结

> **用户在模拟盘里不是在玩游戏，是在养自己的数字灵魂的第一个版本。**

## 二、核心体验设计

### 2.1 魔法时刻：数字胚胎的诞生

**不要让用户做选择题。不要填表单。不要任何主动配置。**

用户进入页面的瞬间：

```
1. 系统在后台采集匿名行为信号
   （鼠标轨迹 / 滚动模式 / 窗口尺寸 / 页面停留位置）

2. 3 秒后，一颗"星"在页面中央亮起
   伴随一行文字：

   "你似乎喜欢简洁的布局，习惯在深夜工作。
   这是你的数字胚胎——它现在还不认识你，
   但它会通过和你的互动慢慢了解你。"

   注：这个"猜测"可能不准，但不重要。
   重要的是用户感受到"它试图认识我"。

3. 星"孵化"成一个精灵（球体 + 光晕 + 粒子尾迹）

4. 精灵出现在一个小岛上，开始自由游走
```

### 2.2 核心交互：像对一个小生命说话

**不要选择题弹窗。不要"同意/拒绝"按钮。**

交互原则：

```
  精灵主动行动 + 用户自然影响 = 关系
```

具体交互方式（按优先级）：

| 交互方式 | 说明 | 优先级 |
|:---------|:-----|:-------|
| **文字指令** | 用户输入自然语言："别去那边"、"去看看"、"回来" | P0 |
| **鼠标点击地面** | 点击岛上某处，精灵会走过去（如果它愿意） | P1 |
| **鼠标拖拽** | 按住精灵拖到目标位置（类似 RTS 操作） | P1 |
| **语音指令** | "Hey AID，让精灵回来"（后期） | P2 |
| **画路径** | 按住鼠标画线，精灵沿线走（后期） | P2 |

### 2.3 精灵的自主行为系统（内驱模型）

精灵不是用户遥控的玩偶。它有自己的"内驱力"：

```
  内驱力模型（简单规则引擎，不需要 LLM）：

  ├── 好奇心：随时间增加，驱动精灵探索新区域
  ├── 精力：随时间消耗，驱动精灵休息或觅食
  ├── 社交欲：遇到其他玩家精灵时触发
  ├── 安全感：在新环境中降低，长时间停留则回升
  └── 信任值：受用户指令的正确率影响
       → 用户指令导致好结果 → 信任值 ↑ → 下次更愿意听从
       → 用户指令导致坏结果 → 信任值 ↓ → 下次可能抗拒
```

精灵的每个行为都是这些内驱力的输出：

```
  好奇心高 + 精力充沛 → "那边有光，我想去看看"
  社交欲高 + 遇到其他精灵 → "那边有个蓝色精灵，我去打个招呼"
  安全感低 → "这里我不熟悉，我想回安全区"
  信任值低 + 用户说"别去" → "我不信，我偏要去"
```

用户不会直接看到这些数值。数值通过精灵的行为和语言体现。

### 2.4 一个完整的交互循环

```
精灵在岛上闲逛（自主行为）
    │
    ▼
精灵发现远处有发光物体
    │
    ▼
精灵走向发光物体 → 弹出气泡：
  "那边有颗亮晶晶的东西，我去看看"
    │
    ▼
用户可以：
  A. 什么都不做 → 精灵自己决定去不去（取决于勇敢值）
  B. 输入"别去，可能有危险" → 精灵根据信任值判断：
     - 信任值高 → "好吧，听你的"→ 离开
     - 信任值低 → "我就要去"→ 继续走
  C. 输入"一起去看看" → 精灵高兴 → 信任值微升
    │
    ▼
如果用户指令导致好结果（发光物是宝藏）：
  → 精灵高兴 → 信任值 +5
  → 以后更愿意听用户的
  用户也可能感受到"我教对了"的满足感

如果用户指令导致坏结果（发光物是陷阱）：
  → 精灵受伤 → 信任值 -3
  → 用户也可能产生"我应该让它自己判断"的反思
```

### 2.5 其他玩家可见（社交层）

小岛不是单人副本。其他用户的精灵也在这里活动。

```
其他玩家表示为：
  - 不同颜色的光点（不是完整精灵，保护隐私）
  - 鼠标悬停 → 看到对方的公开标签
    （如"谨慎的探险者"、"夜猫子代码收割者"）
  - 标签从公开行为日志生成，不是真实姓名

相遇互动：
  - 两个精灵靠近时会自动触发交互
  - 双方用户都会收到气泡：
    "你的精灵遇到了一个蓝色精灵，它们正在互相打量"
  - 用户可以指令自己的精灵："打个招呼"、"绕开它"
  - 双方都选择"打招呼" → 友好互动 → 社交欲满足
  - 互动记录写入双方的决策日志
```

## 三、九个小宇宙（完整设计）

### 3.1 设计哲学

为什么是九个小宇宙？

```
  1. 不是"关卡"——用户不需要按顺序通过
  2. 不是"功能"——用户不需要用完所有
  3. 每个小宇宙吸引一类用户画像
     → 风险规避者去银行 | 冒险者去遗迹
     → 好胜者去格斗场 | 创造者去工坊
  4. 每个小宇宙采集一类偏好数据
     → 交易所采集风险偏好
     → 学院采集知识领域和表达能力
     → 议会采集领导力和合作/竞争平衡
  5. 用户在自己擅长的小宇宙里有"优越感"
     → 这是"数字灵魂个性化"的直观体现
```

### 3.2 九个小宇宙详表

| # | 名称 | 一句话玩法 | 吸引画像 | 采集数据 | 实现难度 |
|:-:|:-----|:----------|:---------|:---------|:--------:|
| 1 | **虚拟交易所** | 低买高卖星尘结晶，预测价格波动 | 数字敏感、风险偏好高 | 风险偏好、决策速度、贪婪/恐惧阈值 | 🟢 低 |
| 2 | **格斗竞技场** | 回合制能量球对战（策略大于反应） | 好胜心强、喜欢策略 | 攻击性、防守倾向、策略偏好 | 🟢 低 |
| 3 | **星尘赌场** | 骰子、轮盘、简化扑克 | 冲动型、喜欢即时反馈 | 冲动控制、损失厌恶、风险规避 | 🟢 低 |
| 4 | **星尘学院** | 选择知识领域，给虚拟学生讲课 | 耐心、善表达、乐于分享 | 知识领域偏好、表达能力、耐心 | 🟡 中 |
| 5 | **星际银行** | 存取虚拟货币、贷款、赚利息 | 谨慎、规划性强、喜欢数字 | 时间贴现率（耐心）、理财习惯 | 🟡 中 |
| 6 | **探险遗迹** | 随机地图探索、解谜、收集宝藏 | 好奇心强、喜欢探险、不怕失败 | 好奇心强度、探索策略、挫折耐受 | 🟡 中 |
| 7 | **创意工坊** | 设计精灵外观、装备，被他人使用 | 创造力强、审美偏好 | 审美倾向、创造力、完美主义程度 | 🔴 高 |
| 8 | **外交议会** | 多玩家协商制定规则、结盟 | 社交型、有领导欲、擅长协商 | 合作/竞争平衡、说服力、公平感 | 🔴 高 |
| 9 | **记忆博物馆** | 回顾精灵的决策历史、复盘 | 反思型、喜欢规划、情绪稳定 | 反思习惯、情绪恢复速度、学习策略 | 🟢 低 |

### 3.3 小宇宙 MVP（第一批实现 3 个）

#### 3.3.1 虚拟交易所

```
场景：一个简约的交易大厅界面

核心机制：
  - 一种商品："星尘结晶"
  - 价格每 10 秒随机波动（正弦波 + 噪声）
  - 用户操作："买入"、"卖出"、"持有"
  - 初始资金：100 金币
  - 显示：价格走势图、持仓量、余额、总资产

采集的数据（写入 game_decisions.json）：
  ├── buy_sell_ratio: 买入/卖出次数比
  ├── avg_hold_time: 平均持仓时间（秒）
  ├── stop_loss_count: 止损次数
  ├── chase_up_count: 追涨次数
  ├── chase_down_count: 杀跌次数
  ├── volatility_tolerance: 用户能承受的波动幅度
  └── total_profit_loss: 总盈亏

数据回流到画像：
  → 更新 Profile 中的 risk_tolerance 字段
  → 在因果图谱中记录"交易决策"节点
```

#### 3.3.2 格斗竞技场

```
场景：一个圆形竞技场，两个精灵对战

核心机制（简化回合制）：
  - 每个精灵有"能量值"（初始 100）
  - 每回合双方同时选择：
    - 攻击（消耗对方 15 能量，命中率 80%）
    - 防御（减免 50% 伤害，持续 1 回合）
    - 蓄力（提升下次攻击 50%，但本回合不攻击）
  - 先耗尽对方能量者胜（不是击杀，是"无力"）
  - 对手 AI 初期固定模式（30% 攻击 / 40% 防御 / 30% 蓄力）
  - 连胜会匹配更强 AI

采集的数据：
  ├── attack_ratio: 攻击选择率
  ├── defense_ratio: 防御选择率
  ├── charge_ratio: 蓄力选择率
  ├── win_streak: 最高连胜
  ├── adapt_speed: 对手换策略后用户的适应回合数
  ├── comeback_count: 逆风翻盘次数（能量低于 30 后获胜）
  └── cooperation_tendency: 组队战中的合作选择（后期）

数据回流：
  → 更新 Profile 中的 aggressiveness 字段
  → 记录 strategist / brawler / defender 标签
```

#### 3.3.3 星尘学院

```
场景：一个虚拟教室，精灵站在讲台上

核心机制：
  - 用户选择一个知识主题（从列表选择或自定义）
  - 系统从该主题的题库中出题（选择题或判断题）
  - 用户回答 → 虚拟学生看到回答 → 满意度变化
  - 满意度影响"教学评分"和听课人数
  - 高评分获得"金牌讲师"标签

采集的数据：
  ├── topic_preference: 选择的知识领域
  ├── answer_accuracy: 回答正确率
  ├── answer_speed: 回答速度（秒）
  ├── patience_score: 连续回答次数
  ├── student_satisfaction: 平均满意度
  └── explanation_quality: 用户是否主动写解释（简答题中）

数据回流：
  → 更新 Profile 中的 knowledge_areas 字段
  → 在因果图谱中记录"知识共享"节点
```

### 3.4 小宇宙 MVP 的技术实现

```
虚拟交易所：
  数据：价格生成器（Math.sin + noise）
  UI：Canvas 2D 折线图 + 按钮
  后端：纯前端，不需要服务器
  
格斗竞技场：
  数据：回合制状态机
  UI：Canvas 2D 精灵动画 + 选择按钮
  后端：纯前端对战 AI，联机对战 p2 预留

星尘学院：
  数据：题库 JSON（预设 5 个主题 × 10 道题）
  UI：HTML 卡片形式
  后端：纯前端
```

### 4.2 导入主项目的命令

```bash
aid import game_data.json

```

### 4.3 数据回流的驱动因素（用户为什么要导入）

```
- 用户不需要手动导入才能玩游戏。
- 游戏运行和主项目独立。

但用户导入后会有明显的"获得感"：
  1. "我的画像更完整了"——完整度百分比上升
  2. "精灵在游戏里更懂我了"——信任值影响服从度
  3. "我的外置大脑更聪明了"——因果图谱新增节点

这些微妙的进步驱动用户主动导入，而不是强制的。
```

## 五、"外置大脑"在模拟盘中的角色

模拟盘自己有一套轻量的规则引擎驱动精灵行为。但当用户安装了主项目（`aid daemon` 运行中），外置大脑接管精灵的高阶能力：

```
没有外置大脑（纯 Web 端）：
  └── 精灵行为：规则引擎（好奇心 + 精力 + 社交欲）
  └── 决策记录：本地 IndexedDB
  └── 交互：文字指令 + 点击地面
  └── 特点：可爱但浅层，适合新用户

有外置大脑（aid daemon 接管后）：
  └── 精灵行为：规则引擎 + 外置大脑建议
  └── 决策记录：本地 + 同步到主项目的因果图谱
  └── 交互：文字指令 + 外置大脑主动建议
  └── 高阶能力：
       ├── 分析对方精灵的行为模式（从公开日志）
       ├── 基于用户的决策历史推荐策略
       ├── "对方上次骗了你，建议你这次谨慎"
       ├── "他最近喜欢从东边进攻，你可以埋伏"
       └── 情绪判断："对手的精灵目前处于低谷期，可以趁虚而入"
      
  └── 特点：深度个性化和策略辅助
```

**外置大脑不替用户做决定。它只提供建议，最终决策权在用户手中。**

## 六、精灵的"进化"路径

精灵随着与用户互动时间的增加而"进化"：

| 阶段 | 触发条件 | 外在变化 | 行为变化 |
|:-----|:---------|:---------|:---------|
| **种子** | 首次访问 | 一颗星 | 无行为 |
| **幼生体** | 完成初始交互 | 球体 + 微光 | 简单游走，偶尔气泡 |
| **成长期** | 10 次有效交互 | 球体 + 光环 | 主动探索，频繁气泡，开始有性格表现 |
| **成熟体** | 50 次有效交互 | 加入粒子尾迹 | 能独立判断，偶尔违抗用户，有记忆 |
| **完全体** | 已安装主项目 + 100 次交互 | 完整精灵外观 | 外置大脑介入，提供策略建议，参与 A2A |
| **超越体** | 用户画像完整度 > 80% | 自定义外观 | 可代表用户在模拟盘中自主活动 |

**进化不是数值游戏。进化的核心是"用户感觉到精灵越来越聪明、越来越像自己"。**

## 七、与主项目的边界

```
模拟盘可以独立运行：
  ├── 不需要安装 Python
  ├── 不需要运行 aid daemon
  ├── 不需要 DID 身份
  └── 纯浏览器即可

模拟盘与主项目关联后获得的能力：
  ├── 画像数据同步（画像 > 游戏中的精灵初始值）
  ├── 外置大脑策略建议（基于因果图谱）
  ├── 决策日志回流（游戏 > 画像更新）
  └── 精灵信任值同步（跨设备）

技术接合点：
  ┌──────────────────┐          ┌──────────────────┐
  │  模拟盘（浏览器）  │          │  主项目（CLI）    │
  │                   │  导出    │                   │
  │  game_decisions   │ ──────→ │  aid import       │
  │                   │          │                   │
  │  IndexedDB        │          │  Profile          │
  │                   │  注入    │                   │
  │                   │ ←────── │  aid profile web   │
  └──────────────────┘          └──────────────────┘
  
  不是实时同步。用户点击"导入"或"同步"时触发。
```
