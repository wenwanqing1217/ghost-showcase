# Alpha-ID 产品设计：Web 端 + 交互体验方案

> 本文档详细描述 Alpha-ID Web 端的产品设计、交互逻辑和用户体验流程。
> 配合《项目总纲》阅读。

---

## 一、Web 端定位

### 不是"官网"，不是"后台"，是"数字世界的入口"

```
传统项目的 Web 端：
  官网（介绍）→ 下载页（获取）→ 控制台（管理）

Alpha-ID 的 Web 端：
  沉浸式入口（体验魔法）→ 个人空间（看到自己的数字存在）
  → 模拟盘（玩耍和贡献数据）→ 下载（需要更多时）
```

### Web 端是用户感知"数字灵魂"的第一触点

用户不需要先安装任何东西。打开浏览器，进入 Web 端，30 秒内就应该感受到：

> "这个项目有点意思——它好像知道我是什么样的人。"

## 三、核心交互流程

### 3.1 用户首次访问（魔法时刻）

```
用户打开 alpha-id.io（或本地 localhost:8899）
    │
    ▼
3D 星链宇宙展开（星座粒子背景）
    │
    ▼
系统自动检测浏览器特征（无需授权敏感数据）：
 ├── 屏幕尺寸 / 窗口比例
 ├── 字体偏好（系统语言）
 ├── 鼠标移动模式（前 10 秒采样）
 ├── 滚动速度 / 深度
 └── 页面停留位置
    │
    ▼
5 秒后，用户看到一颗新的"星"在宇宙中亮起
旁边浮现一行文字：

  "已为你创建数字种子。你似乎习惯在专注时缩小窗口，
   偏好简洁的布局。你的数字胚胎已经开始生长了。"

  （这就已经是魔法了——用户什么都没做，系统就"认识"他了）
    │
    ▼
页面自动进入"星链宇宙"层：
  用户看到自己的星（蓝色光点）在宇宙中缓慢移动
  周围有其他人的星（不同颜色、不同大小）
  鼠标悬停 → 看到标签（不是真实姓名）：
    "夜猫子架构师"  |  "凌晨三点代码收割者"
    "谨慎的探险者"  |  "市场预测师"
    
  注：这些标签不是上传的，是从浏览器本地特征中生成的摘要。
  用户数据没有离开本机。标签是公开的，但可随时关闭。
    │
    ▼
用户可以选择：
  A. 点击"我的空间" → 进入个人画像页（需要安装 CLI 或继续 Web）
  B. 点击"进入创世纪" → 开始玩模拟盘
  C. 浏览项目介绍 → 了解这是什么
  D. 什么都不做，继续看宇宙
```

```
在星链中点击自己的星 → 进入个人空间

页面布局（从左到右）：
┌──────────┬────────────────────────────┬────────────┐
│ 画像摘要  │     因果图谱可视化           │ 精灵状态   │
│          │                            │            │

│ 语言偏好  │      │                     │ [图标]     │
│ 风格倾向  │      │                     │ 等级 Lv.3  │
│ 完整度 72%│      ▼                     │ 勇敢 ████░ │
│          │   [性能焦虑]──导致──>[优化]  │ 合作 ██░░░ │
│          │                            │ 好奇 █████ │
├──────────┴────────────────────────────┴────────────┤
│                    记忆时间线                        │
│  ──── 今天 ─────────────────────────────────────     │
│  14:32  纠正了精灵的一个错误决策 → 信任值+5         │
│  13:00  在交易场中获利 → 风险偏好微调              │
│  昨天                                                     │
│  22:15  在格斗场连胜3场 → 攻击性上升              │
└─────────────────────────────────────────────────────┘
```

### 3.3 宏观到微观的转场（交互亮点）

```
场景：用户在星链宇宙中看到另一个人的星，
       想看看"那个人的精灵在做什么"

点击那颗星 → 视角拉近
    │
    ▼
宇宙背景淡出 → 切入那个用户的公开精灵窗口
    │
    ▼
看到对方的精灵正在某个小宇宙中活动
  （比如在交易场里买卖）
    │
    ▼
可以看到精灵的公开行为：
  "他的精灵刚刚买入了一批星尘结晶"
  "他的精灵正在和另一个精灵互动"
  "他的精灵情绪高涨（连胜中）"
    │
    ▼
无法看到对方的隐私数据（画像细节、决策历史）
  只能看到公开的"行为标签"和"精灵状态"
  
这个转场的意义：
  从"宇宙全景"到"个体视角"无缝过渡
  让用户感受到"每个星背后都有一个活着的数字存在"
```

## 四、技术实现要点

### 4.1 前端技术栈

| 组件 | 技术 | 原因 |
|:-----|:-----|:------|
| 3D 宇宙背景 | Three.js + 粒子系统 | 星链效果的视觉基础 |
| 精灵渲染 | Three.js Sprite + 自定义几何体 | 轻量、可定制 |
| 交互层 | HTML/CSS/JS 透明浮层 | 快速开发、灵活布局 |
| 状态管理 | 本地 IndexedDB | 数据不出本地 |
| 实时同步 | WebSocket 或公共 JSON 轮询 | 轻量级玩家状态同步 |
| 手势交互 | MediaPipe Hands（可选） | 后期增加"手控宇宙"效果 |

### 4.2 数据流（隐私优先）

```
浏览器本地 IndexedDB
    │
    ├── 用户画像摘要（公开字段）：可被 WebSocket 广播
    │     仅包含：行为标签（如"夜猫子架构师"）、精灵等级、当前状态
    │     不包含：真实姓名、具体偏好、决策历史
    │
    ├── 用户画像完整（私有）：仅在本地
    │     包含：所有画像字段、偏好数据、决策日志
    │
    ├── 精灵状态（本地）：精灵的位置、属性、信任值、交互历史
    │
    └── 游戏数据（本地）：所有小宇宙的决策记录
        定期通过 aid import 导入主项目
```

### 4.3 初始"数字种子"生成规则（无需用户操作）

从浏览器行为提取初始特征：

| 行为信号 | 映射维度 | 提取方式 |
|:---------|:---------|:---------|
| 鼠标移动速度 | 活跃度（高/低） | 前 10 秒采样计算平均速度 |
| 滚动深度 | 探索欲（高/低） | 首次加载到开始交互的滚动距离 |
| 窗口大小 | 专注风格（宽屏/窄屏） | screen.width / screen.height |
| 页面停留位置 | 偏好区域（顶部/底部） | 前 5 秒鼠标坐标区域 |
| 点击/悬停行为 | 谨慎度 | 是否点击非强制性元素 |
| 复制内容关键词 | 兴趣领域 | 从剪贴板提取关键词（需浏览器权限） |

**生成的数字种子不精确，不强求准确。**
它只需要让用户感觉"有点意思，它好像猜到了什么"。
如果用户觉得不准，后续的交互（指令、反馈）会自动修正。

## 五、UI 设计语言

### 5.1 视觉基调

| 元素 | 风格 |
|:-----|:------|
| 色彩 | 深色背景（太空感）+ 渐变蓝/紫/金色为主色调 |
| 粒子 | 星尘粒子背景，缓慢旋转，与鼠标位置微弱互动 |
| 字体 | 简洁无衬线，中英文都清晰 |
| 图标 | 线条风格 + 发光效果 |
| 动画 | 流畅缓动，不浮夸，转场有叙事感 |
| 声音 | 可选：低频环境音 + 交互音效（后期） |

### 5.2 关键 UI 元素

```
用户化身（星）：
  - 每个用户一颗星，颜色由初始属性决定
  - 勇敢度高 = 偏红，合作度高 = 偏蓝，好奇度高 = 偏紫
  - 星的大小 = 画像完整度
  - 星的光晕强度 = 活跃度（活跃用户更亮）

精灵：
  - 球体 + 光环 + 粒子尾迹
  - 颜色随属性变化
  - 活泼/安静的行为反映性格
  - 精灵上方有气泡区域，用于显示想法

小宇宙入口：
  - 浮动的图标 + 名称
  - 有"推荐度"指示（火焰/星星/热度）
  - 点击后全屏切换到该小宇宙场景
```

## 六、与主项目的协作关系

```
Web 端                                    主项目（CLI + Daemon）
──────                                    ─────────────────────
初次访问生成数字种子（浏览器行为）         提供真实 DID 身份（安装后）
展示画像摘要（从本地 Profile 读取）        aid profile web → 在 Web 端显示完整画像
模拟盘交互产生决策数据                     aid import game_data → 导入决策数据
显示其他玩家的公开状态（WebSocket）        无状态变更，纯展示
精灵的交互行为                             aid daemon 可接管精灵的"外置大脑"能力

单向数据流：
  Web 端（生成种子 + 游戏决策）→ 导出 JSON → 主项目 import → 画像更新
  主项目（画像数据）→ aid profile web → Web 端展示

不要求实时同步。用户手动触发"导入"即可。
```

## 七、落地优先级

### Web 端 MVP（第一批上线）

| 功能 | 优先级 | 说明 |
|:-----|:-------|:------|
| 3D 星链宇宙（粒子背景） | P0 | 视觉基础，第一个震撼点 |
| 数字种子自动生成 | P0 | 魔法时刻的核心 |
| 个人画像页（摘要） | P0 | 用户看到"它认识我了" |
| "进入创世纪"按钮 + 精灵展示 | P1 | 模拟盘入口 |
| 其他玩家可见（光点） | P1 | 社交感知 |
| 宏观到微观转场 | P2 | 交互亮点，可以后做 |
| 键盘/鼠标操控精灵 | P1 | 核心交互方式 |
| 小宇宙（先做交易所+格斗场） | P1 | 数据采集 |

### Web 端第一批不做的事

| 功能 | 推迟原因 |
|:-----|:---------|
| 实时语音交互 | 依赖浏览器权限和 ASR 服务，MVP 先走文字 |
| 手势粒子控制 | 炫酷但不解决核心问题，放彩蛋清单 |
| DID 签名直接在 Web 端生成 | 安全原因，私钥只由 CLI 管理 |
| 完整因果图谱编辑 | 用户基数上来，有画像数据后再做 |
| 与其他玩家实时聊天 | 社交是 Phase 2 的事 |
| 手机端响应式适配 | 桌面端跑通后再做 |
