## 一、我们到底在做什么

### 一句话回答（对任何人的版本）

> **Alpha-ID 是你的数字灵魂。你在所有 AI 工具中应该是一个连续的存在——换工具、换平台、甚至换设备，你的身份、记忆、偏好自动跟着你走。你的数据在你手里，从不上传任何人。**

### 三句话（对三种人的版本）

| 对象 | 话术 |
|:----|:-----|
| **对用户** | "装一次，你所有的 AI 工具就都认识你了。换工具不用重新介绍自己。" |
| **对开发者** | "一套开源的身份+记忆层，通过 MCP 注入所有 AI 工具。你的 Agent 知道你是在为谁工作。" |
| **对世界** | "每个人的数字存在都应该是连续的、私有的、不可复制的。Alpha-ID 让这件事发生。" |

### Alpha-ID 不是什么

```
❌ 不是"另一个 AI 助手"——你不跟它聊天，它在后台替你活着。
❌ 不是"跨平台登录工具"——不只是身份认证，是完整的人格连续性。
❌ 不是"记忆数据库"——不只是存储，是你的思考和决策方式的数字化。
❌ 不是"框架/SDK"——它不是给开发者用的库，是给你的数字存在。
❌ 不是"平台"——它不绑定任何生态，寄生在所有工具之上。
```

## 三、核心矛盾与选择

| 矛盾 | 选项 A | 选项 B | 我们的选择 |
|:----|:-------|:-------|:-----------|
| **产品 vs 基础设施** | 给终端的消费级产品 | 给开发者的协议/库 | ✅ **消费级产品（用户体验优先）** |
| **广 vs 深** | 全栈数字灵魂 | 只做跨工具身份 | ✅ **全栈，但分层发布** |
| **本地 vs 云** | 完全本地 | 云端优先 | ✅ **本地优先，云端可选** |
| **1.0 策略** | 最小 MVP，快速验证 | 全能力展示，一次性震撼 | ✅ **全能力展示** |
| **严肃工具 vs 游戏化** | 纯生产力工具 | 游戏化交互 | ✅ **两者都要：主项目严肃，子项目游戏化** |

### 关于 1.0 策略的详细说明

我们的策略与其他项目不同：

```
其他项目：
  v1.0：最小可用  →  v1.1：加个功能  →  v2.0：大改版
  
我们的策略：
  v1.0：全模板展现所有能力（身份+记忆+Web+模拟盘）
  v2.0：优化性能、打磨体验、加深度功能
  v3.0：生态开放、A2A 网络、数字遗嘱
```

**原因**：
1. 这是一个全新的品类（数字灵魂），不是已有产品的改进。用户需要看到全貌才能理解你到底在做什么。
2. "魔法时刻"不是单一功能带来的，是**身份 + 记忆 + 可视化 + 交互**组合起来的整体感知。
3. Web 端 + 模拟盘是用户感知魔法的最短路径，必须在一开始就存在。
4. 技术地基（DID + Profile + MCP + 因果图谱）必须在一开始就完整，否则后续迭代都是重建。

### 主项目（CLI + 后台 Daemon）

```
  aid init              → 生成 DID 身份 (did:aid:xxx)
  aid wizard            → 零数据魔法时刻（3 个问题生成初始画像）
  aid collect           → 采集数字足迹（ChatGPT/代码/浏览器）
  aid profile show      → 查看画像（小白模式彩表 / 开发者模式 JSON）
  aid profile web       → 在浏览器中打开画像
  aid mcp install       → 一键注入 Claude Desktop
  aid daemon            → 启动后台常驻进程
  aid inject            → 注入指定 AI 工具
  aid import game_data  → 从模拟盘导入偏好数据
```

### Web 端（用户入口 + 魔法时刻展示）

Web 端不是"一个页面"，而是多层嵌套的沉浸式体验（详见产品设计文档）：

```
  第一层：项目概览 → 这是什么 / 怎么装 / 谁在用
  第二层：实时宇宙 → 看到所有玩家的数字化身在星链中
  第三层：个人空间 → 用户自己的画像、因果图谱、记忆
  第四层：模拟盘入口 → "进入创世纪"按钮
  第五层：宏观到微观 → 从宇宙视角一路缩放到个人视角
```

### 模拟盘 · 数字创世纪（子项目）

这不是"附属游戏"，而是：

```
  ✅ 体验式说明书 —— 用户通过玩理解"外置大脑"是什么
  ✅ 数据采集器 —— 游戏中的每个决策都是偏好数据
  ✅ 病毒传播器 —— "你看我的精灵多聪明"比"你看我的DID"好传播一万倍
  ✅ A2A 试验场 —— 精灵之间的互动是未来 Agent 社交的最小原型
```

核心体验：

```
  用户打开 Web 端 → 系统自动从本机行为提取"数字胚胎"
  → 胚胎在虚拟岛上自由游走、主动提出想法
  → 用户用自然语言影响它（"别去"、"去看看"）
  → 精灵会根据信任值和历史决定是否听从
  → 9 个小宇宙吸引不同画像的用户
  → 数据回流到主项目画像
```

## 五、设计的最高原则

### 原则 1：魔法时刻优先于功能完整

```
  用户不需要理解 DID、MCP、因果图谱。
  用户只需要感知到"它认识我了"。
  
  所以：
    - 先打磨"第一次打开的 30 秒"体验
    - 每一次交互都要让用户感觉"有点东西"
    - 技术细节永远藏在体验下面
```

### 原则 2：小白和开发者是同一套核心的两层界面

```
  小白路径：Web 拖拽 → 看卡片 → 点按钮 → 感知魔法
  开发者路径：pip install → CLI 命令 → JSON 输出 → 脚本化
  
  底层同一套：DID + Profile + MCP + 因果图谱
  上层两层界面：GUI + CLI
```

### 原则 3：用户的数据永远属于用户

```
  - 私钥在客户端，永远不上传
  - Profile 在本地，同步需要用户主动操作
  - 模拟盘数据在本地 IndexedDB
  - "忘记我"按钮一键清除所有本地数据
```

### 原则 4：反脆弱——没有 X 也能工作

```
  没有网络 → 离线模式，所有功能在本地运行
  没有 GPU → 不需要 LLM 推理，规则引擎兜底
  没有 API Key → 本地密钥生成，不进任何云
  没有 MCP → 降级到剪贴板注入
  没有模拟盘 → 主项目独立运行
```

### 原则 5：外置大脑不是 Skill 堆砌

```
  Skill 堆砌 = 菜谱（谁都能照着做）
  外置大脑 = 老厨师（知道什么时候调整、为什么调整）
  
  差异在于：
    1. 独家决策数据 —— 你纠正它、夸它、骂它的历史
    2. 个性化偏好权重 —— 你的"安全 vs 效率"平衡点
    3. 类比迁移能力 —— 把"上次项目延期的决策"用到"今天资源紧张"
    4. 签名隔离 —— 对外协作只暴露摘要，你的核心数据学不走
```
