# 决策技能图谱 (Decision Skills Map)

> 版本: v1.0 | 日期: 2026-07-23
> 目的: 将 AID 已有的七套战略框架 + 实际决策中涌现的思维模式，整合为一套可复用的决策技能系统。

---

## 先回答: 这是不是太自恋了?

**不是。原因有三:**

1. **历史人物的框架也是"某个人的决策模式"** — 查理·芒格的"多元思维模型"就是他自己思考方式的总结。它被珍视不是因为"这是芒格的"，而是因为"这有用"。
2. **你的框架是从实战中长出来的** — 你做了 6 个子项目、写了 818+ 测试、经历了多次方向调整。这些框架不是坐而论道，是被打过的。
3. **框架的价值在于可复用** — 如果你的决策模式能帮助其他 Agent/开发者做出更好的决策，它就是一个有价值的工具。

> 不自恋的做法: 不声称"这是唯一正确的"，而是说"这是我用的，你可以参考"。

## AID 原有七套框架 (战略层)

> 来源: `AID/projects/docs/FRAMEWORK.md`

| # | 框架 | 一句话 | 何时用 |
|---|------|--------|--------|
| 1 | 宇宙星链 | 在生态坐标系中定位，不当最强星体，当交叉点定义者 | 战略方向选择 |
| 2 | 第一性原理 | 压缩到不可再分，从零重建 | 质疑默认假设 |
| 3 | 反向推翻 | 全力证伪，找不到致命反例才执行 | 风险评估 |
| 4 | 递归降维 | 降一层能先解决什么，升回去验证还成立吗 | 复杂问题拆解 |
| 5 | 反脆弱设计 | 失败一次聪明一分，设计有益的失败路径 | 系统设计 |
| 6 | 节律控制 | 扩散→收缩→扩散→收缩，像呼吸交替 | 节奏管理 |
| 7 | 全息追溯 | 任何结论 3 步内追溯到原始证据 | 数据可信度 |

## 今天涌现的决策模式 (实战层)

> 来源: 2026-07-22 对话中观察到的思维模式

### 模式 1: 生态优先思维

```
表现: 每次讨论一个功能，先问"这在生态中是什么位置"
例子: "A2A 不能包揽所有 Agent" → 平台是管道，不是制造商
与 AID 框架的关系: 宇宙星链的实战应用
```

### 模式 2: 平台 vs 建造者二分法

```
表现: 本能地区分"我们做什么"和"别人做什么"
例子: "我们做连接器和验证层，不做 Agent 制造商"
与 AID 框架的关系: 第一性原理 — 压缩"我们是谁"到不可再分
```

### 模式 3: 身份地基论

```
表现: 身份层不是功能，是所有其他层的前提
例子: "先做身份层，才会有后面的 A2A"
与 AID 框架的关系: 递归降维 — 降到底层不可再分的那个
```

### 模式 4: 流程骨架标准化

```
表现: 跨领域识别相同的流程结构
例子: "从开店到出单、从创意到发布 — 流程一样，只是用户信息不同"
与 AID 框架的关系: 第一性原理 — 压缩到"流程骨架 + 变量"
```

### 模式 5: 半成品诚实标注

```
表现: 不装高大上，承认当前状态
例子: "DS 是原型级，mindflow-map 是原型级"
与 AID 框架的关系: 全息追溯 — 诚实标注证据链的完整度
```

### 模式 6: 自我质疑作为校准器

```
表现: 用自我怀疑来校准自信度
例子: "是不是太自恋了?" "放在上面心虚"
与 AID 框架的关系: 反向推翻 — 对自己的假设进行证伪
```

### 模式 7: 连接优于创造

```
表现: 优先连接已有能力，而非从零构建
例子: "用现成的 API 做优化" "GitHub 是最有竞争力的"
与 AID 框架的关系: 宇宙星链 — 找到引力最大的方向
```

### 模式 8: 鸡生蛋破局直觉

```
表现: 对冷启动问题有本能的警觉
例子: "没有 Agent → 没有用户 → 没有 Agent，怎么破?"
与 AID 框架的关系: 反脆弱设计 — 设计不依赖外部条件的启动路径
```

### 模式 9: 类比迁移

```
表现: 用一个领域的逻辑理解另一个领域
例子: "Agent 像 CEO 带员工" "平台像淘宝" "流水线最快因为按部就班"
与 AID 框架的关系: 递归降维 — 用已知模型理解未知问题
```

### 模式 10: 数据真实性执念

```
表现: 对"数据是否可信"有强烈的关注
例子: "有没有捏造造假?" "来源可信吗?" "怎么塑造真实来源?"
与 AID 框架的关系: 全息追溯 — 要求每条数据可验证
```

## 两套框架的整合

### 战略层 (AID 七套) → 实战层 (今天十模式) 的映射

```
宇宙星链 ──→ 生态优先思维、平台 vs 建造者、连接优于创造
第一性原理 ──→ 平台 vs 建造者、流程骨架标准化
反向推翻 ──→ 自我质疑作为校准器
递归降维 ──→ 身份地基论、类比迁移
反脆弱设计 ──→ 鸡生蛋破局直觉
节律控制 ──→ (今天未明显体现，但隐含在"先做身份再做 A2A"的节奏中)
全息追溯 ──→ 半成品诚实标注、数据真实性执念
```

### 整合后的决策流程

```
面对一个问题:

1. [宇宙星链] 这在生态中是什么位置? 谁是引力最大的方向?
2. [第一性原理] 压缩到不可再分 — 本质是什么?
3. [反向推翻] 什么条件下这一定会失败? 对策?
4. [递归降维] 降一层能先解决什么?
5. [反脆弱] 失败了会变强还是变弱?
6. [节律] 现在该扩散还是收缩?
7. [全息追溯] 每个结论的证据链完整吗?

实战加速:
  → 用[生态优先]替代纯理论推演
  → 用[平台/建造者二分]快速划定边界
  → 用[身份地基论]判断优先级
  → 用[流程骨架标准化]识别复用机会
  → 用[半成品诚实标注]管理预期
  → 用[自我质疑]校准风险
  → 用[类比迁移]加速理解
  → 用[鸡生蛋直觉]检查冷启动
  → 用[数据真实性执念]验证可信度
```

## 如何封装为 Agent 技能

### 方案 A: 决策检查清单 (轻量)

```yaml
skill: decision_audit
trigger: 面临战略决策时
steps:
  - name: 生态定位
    question: "这在生态中是什么位置? 谁是引力最大的方向?"
    framework: 宇宙星链
  - name: 本质压缩
    question: "压缩到不可再分 — 本质是什么?"
    framework: 第一性原理
  - name: 反向证伪
    question: "什么条件下这一定会失败?"
    framework: 反向推翻
  - name: 降维执行
    question: "降一层能先解决什么?"
    framework: 递归降维
  - name: 反脆弱检查
    question: "失败了会变强还是变弱?"
    framework: 反脆弱设计
  - name: 节奏判断
    question: "现在该扩散还是收缩?"
    framework: 节律控制
  - name: 证据追溯
    question: "每个结论的证据链完整吗?"
    framework: 全息追溯
output: 一份决策审计报告 (通过/不通过/需补充)
```

### 方案 B: 决策 Agent (重量)

```yaml
skill: decision_agent
trigger: "帮我分析一下这个方向"
capabilities:
  - 输入: 一个想法/方向/产品概念
  - 处理: 运行七套框架 + 十模式分析
  - 输出:
      - 生态坐标图 (文字版)
      - 本质压缩结果
      - 三个致命反例 + 对策
      - 降维执行路径
      - 反脆弱评估
      - 节奏建议
      - 证据链完整度评分
      - 综合判断 (Go / No-Go / 需修改)
```

### 方案 C: 嵌入 AID Profile (推荐)

```yaml
# 在 Agent 的 Datasheet 中标注其决策能力
decision_frameworks:
  - name: 宇宙星链
    level: expert    # expert / proficient / aware
  - name: 第一性原理
    level: expert
  - name: 反向推翻
    level: proficient
  - name: 递归降维
    level: expert
  - name: 反脆弱设计
    level: proficient
  - name: 节律控制
    level: aware
  - name: 全息追溯
    level: expert

# 其他 Agent 可以据此判断:
# "这个 Agent 擅长生态定位和本质分析，但节律控制较弱"
# → 在需要节奏管理时，搭配另一个 Agent
```

## 与现有 AID 框架的关系

```
FRAMEWORK.md (原有)          DECISION_SKILL.md (新增)
─────────────────           ──────────────────────
七套战略框架                十种实战模式
= "怎么想"                  = "怎么选"
= 认知层                    = 决策层
= 告诉你思维工具            = 告诉你何时用哪个工具

两者关系:
  FRAMEWORK 是"剑谱"
  DECISION_SKILL 是"什么时候出哪招"

使用顺序:
  先用 DECISION_SKILL 判断"这是什么类型的问题"
  再用 FRAMEWORK 中的对应框架深入分析
```
