# Ghost / Alpha-ID 完整诊断书

> 基于全网 380+ 文件、52 项问题、14 项修复的审计结果
> 覆盖：架构设计、安全、代码质量、产品设计、运维

---

## 一、架构诊断（6 个问题）

### 1.1 双层 Gateway 架构未落地

**问题：** 文档描述的是"私有网关 + 公共网关"双层隔离，实际只有单层 Gateway。

**影响：** 用户的私有 Agent、隐私数据、本地文件系统和公共外网访问走同一网关。一旦 Gateway 被攻破，内外全暴露。

**建议：** 拆分 Gateway 为两层：
- `:18080` 公共网关 — 外网访问、资讯抓取、A2A 通信
- `:18081` 私有网关 — 仅限 localhost，管控本地 Agent、私钥操作、隐私文件

### 1.2 存储层碎片化（根本问题）

**问题：** 5 种数据读写方式并存。

| 方式 | 位置 | 问题 |
|:-----|:------|:------|
| `SqliteStorage` | core/ | 主流，但也不是统一的 |
| 直连 `sqlite3.connect()` | `registration.py` | 绕过 DI |
| `JsonStorage` | 历史遗留 | 已被取代但代码未删除 |
| 文件系统 `os.walk` | Gateway `memory_search` | 读本地 Obsidian 笔记 |
| SQLite 单独数据库 | `nebula/` | 工作流数据独立 |

**影响：** 改存储逻辑要改 5 处。测试无法统一 mock。

**建议：** 所有数据统一走 `StorageBackend` 接口。`registration.py` 的 4 处直连已确认待修。

### 1.3 双栈撕裂：Python + Node.js

**问题：** `Flow/API` (Node.js) 的注册功能已迁到 Python，但剩余功能（AI 路由、Computer Use）还在 Node 中。Windows 上 Node 进程无法后台驻留。

**影响：** AI 路由功能不可用。Computer Use 不可用。留下了一个"半死不活"的服务。

**建议：** 将 AI 路由功能迁到 Python（alphaid 已有 AgentLoop），彻底移除 Node 依赖。

### 1.4 前端 4300 行单体

**问题：** `ghost.html` 4300 行，CSS 内嵌、JS 内嵌、HTML 混合。9 个面板只有 2 个有数据。全局变量满天飞。

**影响：** 改一个面板要全局搜索。无法写测试。首次加载要下载全部代码。

**建议：** 拆为 3 文件（`ghost.html` + `ghost.css` + `ghost.js`），至少让 JS 可单独测试。

### 1.5 环境变量命名混乱

**问题：** 同一种用途有不同的环境变量名：

| 用途 | 在用变量名 |
|:-----|:-----------|
| 工作区路径 | `COZE_WORKSPACE_PATH`、`GHOST_WORKSPACE_PATH` |
| 存储后端 | `STORAGE_BACKEND`、`DATABASE_URL` |
| LLM API Key | `OPENAI_API_KEY`、`LLM_API_KEY` |
| 模型名 | `LLM_MODEL`、无标准 |

**影响：** 换一个环境就要猜用什么变量名。

**建议：** 统一前缀为 `GHOST_`，所有变量名标准化。

### 1.6 core 模块 70% 死代码

**问题：** `core/` 25 个文件中 18 个是 0 引用死代码（约 6,530 行）。`AgentLoop`、`TwinBrain`、`A2A`、`CoALA`、`事件总线`、`可观测性`、`故障恢复`——全都写完了但没接。

**影响：** 维护成本高。新人看到会困惑"这些模块到底用不用"。真正运行的代码只占 30%。

**建议：** 暂时不用的模块加 `DEPRECATED` 标记，不要删（以后可能用），但让调用关系清晰。

## 二、安全诊断（8 个问题）

### 2.1 百度地图 Token 硬编码在源码（未修）

**位置：** `mindflow/agents/travel.py:15`

**风险：** 🔴 任何人都能看到并用这个 Key。可能导致百度地图账户被盗用产生费用。

**修复：** 已识别为 F-05，待修。

### 2.2 PostgreSQL 密码默认值（未修）

**位置：** `docker-compose.postgres.yml`

**风险：** 🔴 部署到公网不修改密码，数据库直接暴露。

**修复：** 已识别为 F-06，待修。

### 2.3 JWT 签名密钥模块级缓存（未修）

**位置：** `auth/jwt.py:14`

**风险：** 🟡 `MASTER_KEY` 在模块导入时读取一次。运行时修改环境变量不生效。意味着轮换密钥需要重启服务。

**修复：** 改为每次请求时读取环境变量（或至少支持热加载）。

### 2.4 缺少全局请求限流（未修）

**位置：** Gateway 仅对部分路由有限流，alphaid API 无全局限流。

**风险：** 🟡 注册接口无频率限制，可被爆破注册。

### 2.5 XSS 风险（未修）

**位置：** `ghost.html:4271`

**风险：** 🟡 用户搜索关键词直接通过 `innerHTML` 赋值，未转义。攻击者可构造恶意搜索词执行 XSS。

**修复：** 改用 `textContent` 或 `DOMPurify` 消毒。

### 2.6 飞书 WebSocket 无心跳（未修）

**位置：** `nebula/feishu.py:239 行`

**风险：** 🟡 长连接空闲一段时间后服务端断开，客户端检测不到。下次发消息等超时才知道断了。

### 2.7 Ed25519 验签缺失零公钥检查（未修）

**位置：** `did.py:170-192`

**风险：** 🟢 `verify` 函数未检查 `public` 是否为零公钥。零公钥可通过所有验签。

### 2.8 前后端分离无 CSRF 保护（未修）

**位置：** `ghost.html` 所有 fetch 调用

**风险：** 🟡 如果用户登录了 Ghost 后访问恶意网站，该网站可向 Gateway 发跨域请求。

## 三、代码质量诊断（5 个问题）

### 3.1 `registration.py` 直连 SQLite

**位置：** `api/registration.py` 第 57、70、88、98 行

**问题：** 4 处直接调用 `sqlite3.connect(_db_path)`，绕过 Container DI 的存储后端。

**影响：** 测试无法注入 mock 数据库。SMS 验证码和支付宝状态存在主数据库但不受 migration 管理。

### 3.2 core 层解密失败静默吞异常

**位置：** `dual_chain.py:224-227`

**问题：** `get()` 方法中解密失败时返回 `"[解密失败]"` 字符串，不记录日志、不抛出异常。用户看到"解密失败"但不知道为什么。

### 3.3 用户 ID 时间戳冲突

**位置：** `user_identity.py:145`

**问题：** `user_id` 生成依赖 `datetime.now()` 到秒。同一毫秒内并发注册可能产生重复 ID。

### 3.4 全局变量污染

**位置：** `ghost.html:3803-3808`

**问题：** 6 个关键状态变量（`isLoggedIn`、`currentUserDID`、`GATEWAY_URL` 等）全是全局 `var`。任何内联脚本都能读写。

### 3.5 前端硬编码置信度数据

**位置：** `ghost.html:2912、2928、2935、2942`

**问题：** 意图解析面板显示的 "confidence: 0.94"、"0.92" 等是硬编码值，不是从 API 返回的。

## 四、产品设计诊断（4 个问题）

### 4.1 注册后无"啊哈时刻"

**问题：** 用户注册 Alpha-ID 后看到的是空壳面板，没有"注册后第一件事要做什么"的引导。

**影响：** 用户在 30 秒内感受不到价值，直接关掉页面永不回来。

### 4.2 下载站点设计

**问题：** Ghost 官网（`ghost.html`）是产品介绍 + 注册入口。但没有下载站点，用户不知道哪里可以获取更多信息。

### 4.3 没有多语言/国际化

**问题：** 所有界面文字硬编码为中文。如果目标用户包括非中文用户，需要大规模修改。

### 4.4 没有移动端适配

**问题：** `ghost.html` 的 CSS 只用了简单的 `md:` 断点，没有真正测试过移动端显示效果。

## 五、运维诊断（4 个问题）

### 5.1 无发布流程

**问题：** 15 个 PyPI 版本（0.0.1 → 0.3.1）中，没有一次是通过自动化发布的。CI 从未跑绿。

### 5.2 无错误监控

**问题：** 所有错误只写本地日志。线上出问题用户不说没人知道。

### 5.3 无数据库迁移机制

**问题：** SQLite 数据库表结构变更需要手动执行 SQL。每次部署都有人为失误风险。

### 5.4 775 个测试用户无清理策略

**问题：** 数据库中有 775 个 Alpha-ID 用户，全部是测试数据。部署到生产时需要决定是否保留。
