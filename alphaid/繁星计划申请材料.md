## *12 产品

### 解决什么问题？

一句话：**你在所有 AI 工具里应该是同一个人。**

现在的情况：
- ChatGPT 里的你：喜欢简洁回答
- Claude 里的你：喜欢深度分析
- Cursor 里的你：偏好函数式编程
- 豆包里的你：注重隐私

这些"你"互不相通。每次切换工具，AI 都要从零认识你。

更关键的是：当 Agent 开始替你行动时——发邮件、写代码、做决策——它不知道"你是谁"。这不只是体验问题，是安全问题。

### 怎么解决？

Alpha-ID 是一个**坐在所有 AI 工具之上的身份层**。不造新 AI，让已有 AI 认识你。

**核心机制**：

1. **你的数字身份**：在你的设备上生成一个唯一的去中心化身份（DID），私钥永远在你手里，不上传任何人。你拥有自己的身份，不是平台拥有。

2. **你的数字画像**：从你的日常行为中自动提取——你偏好什么风格、什么时段活跃、什么技术栈、什么思维方式。不是让你填问卷，是观察你的行为。

3. **你的数字记忆**：三层记忆架构，像人脑一样——工作记忆（当前在做什么）、情景记忆（昨天发生了什么）、语义记忆（你是什么样的人）。记忆会随时间"重固化"，每次使用都可能被修正。

4. **一键注入所有 AI 工具**：基于 MCP 协议，一条命令让 Claude、Cursor、Windsurf 等工具都"认识"你。你的风格、偏好、记忆，自动注入。

**当前进展**：

- Phase 0 已完成：CLI 工具 `aid` 可用，完整流程跑通
  - `aid init` → 生成身份
  - `aid collect chatgpt <zip>` → 导入对话历史
  - `aid profile show` → 查看你的画像
  - `aid mcp install` → 一键注入 Claude Desktop
- 715 项测试全部通过，CI/CD 就绪
- Web 展示层原型已完成

**商业模式**：

Alpha-ID 定位为基础设施层——**存在即免费**。核心身份层和画像功能永久免费开源。商业模式基于增值服务：高级记忆分析、多设备同步、企业级身份管理与审计。

## *14 竞争

### 真正在打的仗

大多数 AI 项目在**显性战场**竞争：更快的模型、更多的功能、更便宜的 API。

Alpha-ID 在**隐性战场**竞争：
- 这个 Agent 代表谁？（身份层）
- 它为什么做这个决定？（因果追溯）
- 它有多像你？（个性化深度）
- 用户不在时它在做什么？（持续存在）

### 竞品对比

| 竞品 | 他们做什么 | Alpha-ID 的不同 |
|:-----|:----------|:----------------|
| **Coze（扣子）** | AI 应用平台，多 Agent 协作 | 平台 vs 层——Coze 解决"怎么用 AI"，Alpha-ID 解决"AI 是谁在用"。**互补，不是竞争** |
| **Mem0 / Zep** | 单工具记忆增强 | 只做记忆，不做跨工具身份连续性 |
| **Willow（$7M 融资）** | Agent 身份管理 | 直接竞品，但 Alpha-ID 有本地优先+因果图谱的差异化 |

### 核心护城河

**Skill 可以复制，你和你的 Agent 之间的历史不可复制。**

就像两个人可以买同一台相机，但拍出来的照片永远不会一样——因为底片上的内容不同。你的"底片"是你过去所有的数字痕迹、决策记录、偏好数据。这些别人复制不走。

具体来说：
1. **本地优先**：数据不离开设备，这是架构决定的，竞品改不了
2. **因果图谱**：不只记住"你做了什么"，还记住"你为什么这么做"
3. **信任历史**：用户和 Agent 之间的每一次交互都不可逆地积累
4. **开源协议**：基于 MCP + A2A 开放协议，不造私有协议，生态兼容性强

### 一个更深的思考

我们正在进入一个"Agent 代理一切"的时代。

当你让 Agent 帮你发邮件、写代码、做决策时，**"谁在调用"变得比"调用什么"更重要**。

HTTPS 之于 Web，让信息传输变得可信。Alpha-ID 之于 AI，要让 Agent 行为变得可溯源、可审计、可信任。

这不是一个应用。这是一层基础设施。

> *"Skill 可以被复制。你和你的 Agent 之间的历史，不可复制。"*
