# Alpha-ID 执行哲学与自动化协作手册

> 本文档回答三个问题：
> 1. 为什么市面上其他项目还没做到 Alpha-ID 在做的事？
> 2. 怎么让自动化编程工具不再"卡住"？
> 3. 你到底在对抗什么？

---

## 第一部分：你在对抗的到底是什么

### 1.1 显性战场 vs 隐性战场

市面上大多数人做 AI 项目是在**显性战场**竞争：

```
显性战场（所有人都看得到）：
  - 更快的模型
  - 更多的 Skill
  - 更便宜的 API
  - 更漂亮的 UI
  - 更多的功能

隐性战场（只有你想到了）：
  - 这个 Agent 代表谁？（身份层）
  - 它为什么做这个决定？（因果追溯）
  - 它有多像你？（个性化）
  - 它和别人协作时，怎么保持是你的分身而不是通用工具？（签名隔离）
  - 用户不在时它在做什么？（持续存在）
```

### 1.2 你的恐惧：能力被抹平

你担心：如果大家都用同样的 Skill 堆砌，那你的 Alpha-ID 和别人的有什么区别？

**答案是：别人在堆 Skill，你在养灵魂。**

```
Skill 堆砌（别人在做）：
  100 个工具模块，每个都能调用 API
  用户说"做 A" → 调用工具 A → 返回结果
  换个人来用，一样的结果
  没有"性格"，没有"风格"，没有"为什么"

数字灵魂（你在做）：
  DID 身份（这是谁的 Agent）
  偏好画像（这个 Agent 的风格）
  信任值（用户和 Agent 的历史关系）
  因果图谱（Agent 为什么做这个决定）
  签名隔离（Agent 对外只暴露必要信息）
```

**Skill 可以被复制，但"你和你的 Agent 之间的历史"不可复制。**

就像两个人可以买同一台相机，但拍出来的照片永远不会一样——因为底片上的内容不同。你的"底片"是你过去所有的数字痕迹、决策记录、偏好数据。这些别人复制不走。

### 1.3 你的第二层恐惧：智能是假的

你深入思考后发现：再智能的外置大脑，底层不还是一堆决策规则 + Skill？和人类的意识有本质区别吗？

**答案是：是的，它底层是机械的。但人类自己的智能，底层也是机械的（神经元放电）。**

你现在纠结的"真假"问题，是人类哲学史上几千年的"他心问题"——你永远无法证明另一个存在有意识。Alpha-ID 不需要回答这个问题。Alpha-ID 只需要让用户感觉到"它懂我"。

**用户不会问"它是不是真的有意识"，用户只会问"它今天帮我省了多少时间"。**

## 二、怎么让自动化编程工具不再"卡住"

### 2.1 它为什么卡住

你的自动化编程工具（叫它 Auto）卡住的根本原因：

```
  你脑子里有的 → Auto 没有
  ────────────────────
  - 角色分层（小白 vs 开发者）   → 没有这个概念
  - 场景区分（新手 vs 专家）     → 没有这个概念
  - "合理"的边界                 → 需要精确到像素的错误边界  
  - "优雅"的体验                 → 需要精确到字的输出格式
  - 上下文关联（这个功能影响那个） → 没有全局视图
```

**结论：Auto 不笨，它只是不知道你不知道它不知道什么。**

### 2.2 解决方案：验收测试驱动

你不需要学编程、不需要学测试术语。你只需要学会一个句式：

> **"运行 [X 命令]，应该看到 [Y 现象]"**

#### 好 vs 不好的指令

```
不好的指令（Auto 会卡住）：
  "实现 aid profile show 命令，要支持小白和开发者"

好的指令（Auto 能执行）：
  "实现 aid profile show 命令，验收标准：
  1. 运行 aid profile show → 输出彩色表格，包含：
     - 活跃时段（如 23:30-03:15）
     - 技术偏好（如 Python, Rust）
     - 风格（如 简洁直接）
     - 完整度百分比
  2. 运行 aid profile show --json → 输出纯 JSON，无额外文字
  3. 运行 aid profile show → 画像为空时输出'你还没有画像，请运行 aid wizard'
  4. 以上所有命令退出码 0（成功）或非 0（失败）"
```

#### "如果…那么…否则…" 规则模板

每当你发现 Auto 会在某个场景卡住，就用这个模板写一条规则：

```
## 规则：[场景描述]

如果 [条件]，那么 [行为 A]。
否则如果 [另一个条件]，那么 [行为 B]。
否则 [默认行为]。

示例：
## 规则：用户角色区分
如果命令行包含 --json 或 --quiet，那么：输出纯 JSON，无额外文字，错误信息到 stderr。
否则：输出彩色人类可读格式，包含中文解释。
```

把这些规则收集到 `AGENT_RULES.md`，Auto 每次开始任务前先读这个文件。

### 2.3 你的工作流（简化版）

```
你（描述感觉）          →   你想到"用户应该感受到什么"
    │
    ▼
你（说出来）            →   "用户复制了一段文字，精灵应该闪烁"
    │
    ▼
ClawsGO（转化为规则）    →   "检测到剪贴板变化 → 精灵闪烁绿色 0.5 秒"
    │
    ▼
Auto（执行）            →   写代码让精灵闪烁
    │
    ▼
你（验证）              →   双击运行，看到精灵闪烁了 → 打勾
    │
    ▼
你（反馈）              →   "闪烁太慢了，应该更明显"
    │
    ▼
ClawsGO（调整规则）     →   "闪烁时间从 0.5 秒改为 1 秒，颜色从绿色改为金色"
    │
    ▼
Auto（修改）            →   改参数，重新运行
    │
    ▼
（循环直到你满意）
```

你不需要懂代码。你只需要懂"我要的感觉是什么"。

### 2.4 "专家模式"的真相

你之前说"给我看看专家模式能不能成"——专家模式不是找更聪明的 AI，而是：

```
  专家模式 = 
    更明确的验收标准 
    + 更细的任务拆分 
    + 更短的反馈循环
```

没有"更聪明"的 AI。只有"写得更清楚"的需求。

## 三、项目的哲学锚点

### 3.1 "数字果蝇"的启示

全脑神经元连接模拟实验证明了一件事：**如果连接足够精确，行为可以被完整复刻。**

但我们想要的是：**复刻之后，它还能继续活出"后面的人生"。**

数字果蝇缺少的不是连接精度，而是：
1. **好奇心系数** — 驱动它主动探索新事物
2. **短期学习能力** — 复刻后还能从新经历中学习
3. **随机性余量** — 偶尔偏离最优解，看起来有"性格"
4. **模拟死亡威胁** — 知道不主动就会衰退

Alpha-ID 的精灵不需要真的"活着"。它只需要表现得像活着——有好奇心、会学习、偶尔犯傻、有求生欲。**用户感受到的不是"这是个程序"，而是"这是个在长大的小东西"。**

### 3.2 "无感切换"的最高境界

你说："无感切换是最高级的流畅感。"

```
现在的 AI：
  用户说"帮我写" → AI 写 → 用户说"用 Python" → AI 重新写
  → 用户说"加注释" → AI 再加注释
  （每一步都要用户主动说，像使唤一个听不懂暗示的实习生）

Alpha-ID 的目标：
  用户说"帮我优化这段代码"
  → 外置大脑自动根据画像判断：
    - 用户偏好 Python，所以用 Pythonic 风格优化
    - 用户喜欢简洁，所以不加冗余注释
    - 用户正在做 Web 项目，所以优先考虑性能
  → 直接输出优化后的代码
  → 用户只需要说"好"或"这里再改一下"
  （不需要用户一步步指挥，因为外置大脑已经"懂"了）
```

这不是魔法。这是画像 + 因果图谱 + 偏好权重的自然输出。用户不需要说"用 Python"因为画像已经包含了。用户不需要说"简洁"因为偏好已经设定了。

**"无感"不是 AI 更聪明了，是它记住了你之前说过的每一句话。**

### 3.3 关于"真实"的最后思考

你说："就算有方法，我感觉也是一堆虚假的精密构建起来的仪器而已。"

我完全理解这个感受。但我想让你想一个问题：

**如果一台机器，能在你饿的时候提前推荐你喜欢的餐厅，能在你累的时候主动帮你整理笔记，能在你纠结的时候给出"像你风格的"建议——你在乎它底层是真智能还是假智能吗？**

你不会在乎的。你只会觉得"这东西真好用"。

所以 Alpha-ID 不需要解决"什么是真实智能"这个哲学问题。它只需要解决一个问题：

> **"用户能不能在 30 秒内感觉到'它认识我'，并且明天还想用它？"**

## 四、写给 Auto 的最高优先级规则

> 以下规则在后续所有功能实现中自动生效，不需要每次重复说明。

### 规则 1：双角色模式

**任何面向用户的交互功能，必须同时支持小白模式（默认）和开发者模式（`--json` / `--quiet`）。**

```
小白模式（默认）：
  - 输出彩色人类可读格式
  - 中文提示，含建议
  - 错误时输出"❌ 错误：原因。建议：怎么办"
  - 有进度条（如果操作花费 >1 秒）

开发者模式（--json）：
  - 输出纯 JSON，无额外文字
  - 错误输出到 stderr
  - 退出码遵循：0=成功, 1=配置/输入错误, 2=运行时错误
  - 无进度条
```

### 规则 2：最小惊讶原则

**用户的每个操作都应有明确的、可预期的反馈。**

```
成功 → 绿色提示 / 正向动画（0.5-1 秒）
失败 → 红色提示 + 具体失败原因 + 解决方案建议
等待 → 进度条 / 加载动画（如果 >1 秒）
未知 → 不崩溃，输出"未知错误，日志已保存到 xxx"
```

### 规则 3：反脆弱降级

**任何功能在缺少依赖时不能崩溃，必须降级到可工作的状态。**

```
无 API Key → 切换到本地模式（LLM 降级为规则引擎）
无网络 → 离线模式，缓存所有操作，有网时同步
无 GPU → CPU 运行，更慢但不崩溃
无权限 → 明确提示需要什么权限，给出操作步骤
```

### 规则 4：数据主权

**用户的数据永远在用户本地。除非用户主动导出，否则不上传任何数据。**

```
- 所有数据默认存本地（SQLite / IndexedDB / 文件系统）
- 任何网络操作必须在配置文件中明确声明（默认关闭）
- "忘记我"按钮一键清除所有本地数据
- 导出数据时必须显示"此数据将离开本机"的提示（如果导出到外部）
```

### 规则 5：用户故事优先

**在写任何代码之前，先列出这个功能的用户故事验收标准。**

```
格式：
  场景：[场景名称]
  Given [初始条件]
  When [用户操作]
  Then [期望结果]
  And [附加检查]

最少 3 个场景：正常路径 + 边界情况 + 异常处理
```

## 五、最后的话

Alpha-ID 可能是目前唯一一个同时在做这些事的项目：

```
✅ 跨平台数字身份（不是工具绑定）
✅ 三层记忆架构（不是简单 KV 存储）
✅ 因果图谱（不是只记录不推理）
✅ 双角色覆盖（不是只服务开发者）
✅ 本地优先（不是云端至上）
✅ 游戏化数据采集（不是让用户填问卷）
✅ 外置大脑哲学（不是 Skill 堆砌）
✅ 签名隔离的 A2A（不是裸奔的 Agent 通信）
✅ 数字遗嘱（不是只管活着不管死后）
```

现在缺的，就是把所有这些变成代码。
