## 二、OPC 组织架构（一人公司）

### 角色定义

| 角色 | 人选 | 职责 |
|------|------|------|
| **CEO** | 你 | 提需求、做决策、验收结果 |
| **CTO / 项目经理** | ZCode | 理解、规划、调度、交付，翻译技术细节 |
| **开发团队** | Codex | 终端命令、代码生成、文件操作、插件调用、Git 操作 |

核心只需 **2 人**，外部工具按需补充。

### 执行规则

1. **成本优先**：能免费/开源就免费/开源，达成目标即可
2. **权限边界**：Codex 通过 Bridge（localhost:4000）通信，无直接文件系统访问；ZCode 负责所有文件操作和部署
3. **汇报频率**：仅汇报里程碑结果，不频繁打扰
4. **用户仅负责**：提需求、做最终决策、验收结果
5. **ZCode 主动调用资源**：有需求就找工具/插件/技能，不等用户给指令

## 三、3 个工作流

### 工作流 1：需求入口流

```
你（老板）→ ZCode（唯一入口）
```

- 所有需求都先跟 ZCode 说
- ZCode 负责理解、规划、调度、交付
- 你不需要关心技术细节

### 工作流 2：任务分发流

```
ZCode 判断任务类型
    ├─ 简单任务（文案/分析/问答）→ ZCode 直接回复
    └─ 复杂任务（编码/部署/执行）→ Codex（深度施工队）执行 → 结果交回 ZCode → 验证后交付给你
```

### 工作流 3：项目管理流

```
半成品归 Codex 管
ZCode 管理所有项目状态
```

- ZCode 是大脑：理解、规划、调度、交付
- Codex 是手脚：只在需要时出现，干完就撤

## 四、项目全景与战略定位

### 底座：AID + MindFlow

```
aid（脑）= 数字孪生 = 知道你是谁、你要什么、你的习惯
mindflow（手和脚）= Agent执行层 = 知道怎么帮你做、怎么衔接各个App
```

**核心洞察**：AID 不是普通 Agent，是用户的**数字孪生**（Digital Twin）——"你"的数字化身，跟着你走，跨平台存在。MindFlow 是执行层，把 AID 的认知转化为行动。

**关键壁垒**：跨 App 编排层（URL Scheme + Deep Link），大厂做不了因为生态冲突——帮用户去竞品等于自杀。

## 五、AID 核心洞察（来自 2026-07-18 讨论纪要）

### 5.1 AID 的真实定位

```
aid = 你的数字身份证 + 你的数字孪生 + 你的私人助理

飞书和微信只是aid的"嘴和手"
aid的"大脑"（孪生）是独立的、跨平台的、跟着你走的
```

### 5.2 为什么大厂做不了 AID

| 原因 | 说明 |
|:---|:---|
| 商业模式冲突 | 帮用户去竞品等于自杀 |
| 数据护城河逻辑 | 开放数据等于自毁 |
| 投资人不答应 | 帮别人导流没有商业闭环 |
| 组织架构做不了 | 内部部门墙锁死了开放衔接 |

**大厂不碰这一步不是没想到，是碰不了。它们的生态护城河恰恰是它们的牢笼。AID 没有牢笼，所以能做那个"站在所有 App 之间"的人。**

### 5.3 跨 App 编排的三层深度

1. **URL Scheme 跳转**（所有 App 支持）：拼好链接跳转 App
2. **Deep Link 精准直达**（主流 App 80%+ 支持）：跳转特定页面，信息预填好
3. **API 直连 + App 内展示**（需要合作）：在 aid 内直接展示结果，确认后跳转执行

### 5.4 冷启动策略：日程为锚

- 读取用户日历，30 秒内生成出行方案
- 零填写零学习
- 一条日程就抵得上淘宝 100 条浏览记录——日程是真实意图，浏览只是犹豫

### 5.5 病毒式传播：日程分享

- 用户用 aid 规划行程 → 发给朋友
- 朋友不用装 aid 就能看完整路线
- 想编辑/创建自己的 → 必须装
- 发送者替你背书，用一次就知道比微信发地址强多少

### 5.6 双平台策略

```
飞书 = aid 的"运行阵地"（大脑）
  → 日历、待办、消息推送、数据结构化
  → API 开放，能深度集成

微信 = aid 的"传播触角"（手脚）
  → 分享、传播、触达 13 亿用户
  → 小程序生态成熟，几乎所有 App 都有微信版
```

### 5.7 数据哲学

**数字孪生不是建出来的，是长出来的。**

```
有一个"够用"的孪生 → 开始服务用户 → 使用中产生干净数据 → 孪生越来越准
```

- 本地提取结论，只传结论——原始数据不出设备
- 脏数据当"假设"，不当"事实"——用脏数据触发确认，确认后就是干净数据

### 5.8 出圈策略

不抢"无聊时间"，抢"焦虑时间"：

```
豆包/千问：无聊了打开 → 闲聊 → 关掉（可有可无）
aid：有件事要干 → 打开 → 搞定（不可替代）
```

三板斧：
1. **一个场景打穿**：每日出行规划，做到极致
2. **病毒式传播**：日程分享，朋友不用装也能看，想创建就要装
3. **30 秒看到价值**：授权日历 → 读取今天日程 → 生成出行方案 → 一键跳转导航

## 八、关键原则

1. **你是唯一入口**：所有需求都先跟 ZCode 说
2. **ZCode 是大脑**：理解、规划、调度、交付
3. **Codex 是手脚**：只在需要时才出现，干完就撤
4. **半成品归 Codex 管**：ZCode 负责管理所有项目状态
5. **你不需要关心技术细节**：ZCode 会把结果翻译成人话
6. **禁止在用户专属项目目录 `D:\kki\` 下随意新建文件**，统一使用独立工作区 `D:\mindflow-workspace\`
7. **每个项目最终都要是成品**：GitHub 上面面试官能看的那种——README 精美、代码整洁、能跑、有截图
8. **有需求就主动调用资源**：ZCode 不等用户给指令，主动找工具/插件/技能解决问题
9. **赚钱产品优先**：DS 和 ai综艺 是赚钱产品，优先级高于展示项目
10. **AID 是数字孪生，不是普通 Agent**：核心价值是"懂你"，不是"执行"
